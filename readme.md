# Modular D&D Dungeon Board

A laser-cut dungeon table for the **AlgoLaser DIY Kit MK2**. Four sheets of
400×400×3mm plywood become a **600×600mm, 20×20-square** board plus a full
starter kit of walls, doors, figures and props. Nothing is bought but the
plywood; nothing is glued.

Every file is generated by `generate.py`, so when a test cut tells you the real
thickness and kerf, you change two numbers and regenerate the lot.

---

## Quick start

```bash
python generate.py --report      # writes out/*.svg, prints cut lengths and a bounds check
python sanity_check.py           # dimensional check: every joint, post-kerf
python super_check.py            # structural check of the written SVGs
```

A second set for other plywood, checks included:

```bash
python generate.py  --thickness 2.6 --out out_2.6mm --report
python sanity_check.py --thickness 2.6 --out out_2.6mm
python super_check.py  --thickness 2.6 --out out_2.6mm
```

`out/` is built for 3mm and `out_2.6mm/` for 2.6mm; both are generated and
verified. The fit-test coupon re-centres its slot sweep on whichever thickness
you generate for.

1. **Cut `out/00_fit_test.svg` on scrap first.** Five minutes. Do not skip it.
2. Measure it (below), set `THICKNESS` and `KERF` in `generate.py`, re-run.
3. Cut `01_sheet_A.svg`. Assemble a wall, a corner and a figure to confirm.
4. Cut sheets B, C, D.

Requires Python 3 only — no packages to install.

The two reference pages are also written as **300 dpi PNGs** on every run
(4724×3508 and 6614×4724 px). An SVG will not go in a phone's photo roll or
print predictably, and these are the two files you actually want at the table.
It needs Inkscape, `rsvg-convert` or ImageMagick on the PATH; without one the
SVGs are still written and the run says so. `--no-png` skips it, `--dpi 600`
doubles it.

## Software

**Inkscape** (free) to view and tweak. **LightBurn** to run the job — 30-day
free trial, ~$70 GCode licence. It is the only one of the options that maps SVG
colours to cut/engrave layers, which this design needs. LaserGRBL and AlgoLaser
Design Space are free but clumsy for multi-layer vector work.

### LightBurn setup

Device: **GRBL**, 400×400, origin front-left. Import the SVG and set the layers
by colour:

| Colour | Layer | Mode | Order |
|---|---|---|---|
| `#0000FF` blue | grid lines | Line | 1st |
| `#00FF00` green | art, stone texture, labels | Line | 2nd |
| `#FF0000` red | everything cut | Line | **last** |
| `#000000` black | 380mm reference frame | **output OFF** | — |

Two settings that matter:

- **Engrave layers must run before the cut layer.** Otherwise you are engraving
  over holes that are already open, and burning the table underneath.
- Turn on **"cut inner shapes first"**. The 81 interior holes have to be cut
  before the tile perimeter releases the piece.

Check the black frame measures exactly **380mm** after import. If it does not,
the SVG scaled wrong and every joint will be off.

### Starting settings

Tune these; they are a starting point, not gospel.

| Module | Cut 3mm ply | Per sheet |
|---|---|---|
| 5W | 150 mm/min, 100%, 6 passes | ~5 h — marginal, consider 3mm basswood |
| **10W** | **250 mm/min, 100%, 3–4 passes** | **~2 h** |
| 20W | 400 mm/min, 100%, 2 passes | ~45 min |

Engrave: grid 3000 mm/min @ 15%, stone texture and art 3000 mm/min @ 10%.

Roughly **8.5 hours for all four sheets on a 10W module** at 4 passes, about 6.5
at 3. Three things cut that down and improve the edges a lot:

- **Air assist.** A €10 aquarium pump aimed at the nozzle roughly halves the
  passes and removes most of the charring.
- **Masking tape** on the top face, peeled after cutting: no scorch halo.
- **Flat hold-down.** The focus has to stay constant across 380mm.

Diode laser plus plywood is a real fire risk. Never run it unattended,
ventilate, wear the glasses.

## Checking the scale

A file that imports at the wrong scale looks completely normal on screen and
quietly produces a board where nothing fits. Nothing in the files can catch
that, so check it against a known dimension.

**The best moment is between the engrave and the cut.** Engraving runs first, so
once the blue and green layers finish, the grid is on the wood and nothing has
been cut. Measure ten grid squares corner to corner: it must read **300mm**. If
it does not, stop — no plywood is wasted yet.

| Measure this | 3mm set | 2.6mm set |
|---|---|---|
| 10 engraved grid squares, corner to corner | **300.0mm** | **300.0mm** |
| One grid square | 30.0mm | 30.0mm |
| Board tile, edge to edge | 300.0mm | 300.0mm |
| Vertex hole, across the flats | 6.0mm | 6.0mm |
| Wall, 1 / 2 / 3 / 5 squares — length | 30 / 60 / 90 / 150mm | 30 / 60 / 90 / 150mm |
| Wall height, body + tab | 17.0mm | 16.6mm |
| Corner plate, length | 31.5mm | 31.3mm |
| Door, length | 30.0mm | 30.0mm |
| Seam key, square | 6.0mm | 6.0mm |
| Black reference frame — on screen only | 380.0mm | 380.0mm |

Only the last two piece rows differ between sets, because a wall's tab is as
deep as the plywood is thick.

## The fit test

`00_fit_test.svg` is a ~96×116mm coupon. It settles the only two numbers the
whole kit depends on.

- **SLOT row** — seven slots, drawn 2.6 → 3.2mm. Push a plywood offcut in
  edge-on. The snuggest one that goes in without forcing tells you the effective
  slot width. If slot *n* is right, then `THICKNESS - 2*KERF = n`.
- **HOLE row** — six squares, drawn 5.4 → 5.9mm. The wall tab on the same coupon
  should be snug in one of them.
- **Wall + key + half-lap pair** — assemble them for real.

Measure your plywood with calipers in three places, set `THICKNESS` to the
average, then set `KERF = (THICKNESS - best_slot) / 2`. Re-run `generate.py`.

Joints loose? Raise `KERF` by 0.05 and regenerate. Too tight? Lower it.

## The piece list

`out/07_piece_list.svg` is generated on every run, from the same geometry that
goes into the cut files — so it cannot drift out of step with what the laser
actually produced. One column per sheet, grouped board / terrain / figures /
bases, and each row carries a thumbnail at true relative size, how many that
sheet holds, and the dimension that matters for that kind of part. It is written
as `07_piece_list.png` too, so you can keep it open on a phone at the table.

Two things it is worth opening for:

- **Sorting the pile after a cut.** 181 pieces come off four sheets. The
  thumbnails are what let you tell a corner plate from a 1-square wall.
- **Matching bases to figures.** Bases are cut to fit their figure, so a base
  row says which figures it belongs to — `SLOTTED - FOR MAGE ROGUE` — rather
  than just quoting a diameter.

Add a monster to `sheet_pieces()` and the list grows a row on its own;
`sanity_check.py` re-checks that every packed piece still appears on it and that
the column still fits the page.

## Assembly

Open `out/06_assembly.svg` — it draws the real geometry, at size.

### The board

Butt the four tiles together. There are no connectors: the outer ring of grid
vertices sits exactly on the tile edge, so those holes are cut in half and two
butted tiles reform a whole hole across the seam. The grid runs continuously, a
wall can stand right on the join, and dropping a **seam key** into any seam hole
locks the tiles laterally, flush with the surface.

The table's *outer* perimeter has only half-holes, so no walls right on the very
edge. One square in is fine.

### Walls

Wall bodies run the full vertex-to-vertex length, so collinear walls **butt with
no visible gap**. Each end has a tab that occupies the **near half** of its
vertex hole, which is why two walls can meet at one vertex without their tabs
fighting. Push down until the tab is flush underneath.

Walls come 1, 2, 3 and 5 squares long. Use the longest piece that fits a run —
seams then only appear where you want them, at corners and doorways.

### Corners

**Only one wall direction can use a vertex.** Two walls crossing at 90° would
both need the middle of the same hole. That is what the L-corner is for.

Each L is two plates: one rebated from the top, one from the bottom. Cross them
at 90° and slide together — they interlock into a rigid L that fills the corner
with no gap. The corner vertex itself takes no tab; the L is held by the tabs at
its two far ends. The same trick makes T- and X-junctions if you want them.

### Figures

Each figure presses into its own slotted disc base. Push until the figure's feet
are flush with the underside of the base — friction holds it, so do not force a
tight one; sand the tab edge instead.

Bases are sized per figure (24–28mm, dragon 36mm), so keep each figure with the
base cut next to it.

## How the art survives being cut

The class meeples carry weapons, cloaks and shields separated from the body by
slits **0.19–1.15mm wide** at 24mm tall — narrower than the laser kerf, so those
features would simply fall out.

So the cut line is not the artwork. `outline.py` fills the silhouette into a
bitmap, applies a morphological **closing** (dilate then erode by 0.8mm), and
re-traces it. Slits narrower than 1.6mm merge into solid wood while the outer
profile stays put; the narrowest neck goes from 0.19mm to at least 1.46mm. The
original art is then engraved on top, clipped to sit inside the cut line, so the
detail is all still visible — it just is not a structural hole any more.

Same treatment at 0.45mm for the monsters.

## Changing things

Everything lives in the CONFIG block of `generate.py`.

| Want | Change |
|---|---|
| Different plywood | `--thickness 2.8 --out out_2.8mm`, or edit `THICKNESS` |
| Faster cutting | `HOLE` 6.0 → 5.0 saves ~0.5m per sheet (thinner tabs) |
| No stone texture | `STONE_TEXTURE = False`, saves ~9m of engraving per sheet |
| Taller walls | `WALL_H`; above ~18mm they stop fitting two rows to a strip |
| Different heroes | `meeples.HEROES` — any of the 16 class files by name |
| More artwork | Drop SVGs into `Meeples svg/`; black = cut, green = engrave |

`--report` prints cut length, engrave length, a time estimate per module, and
fails loudly if anything falls outside the 380mm safe area or will not fit on a
sheet.

After changing anything, re-run both checks. `sanity_check.py` verifies the
finished size of every joint after kerf and that the piece list still matches
the sheets; `super_check.py` re-reads the written
SVGs and looks for open contours, crossing cut paths, loose islands, engraving
on the wrong part, and features too thin to survive 3mm ply.
